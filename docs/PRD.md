# 鸿蒙微博客户端｜首版产品需求

状态：开发依据（接口能力待真机验证）
更新：2026-11-25

## 1. 目标与用户

为个人使用制作 HarmonyOS 7 手机客户端，让用户在原生界面中浏览微博、查看视频并完成评论和点赞。首版以真实微博账号和真实内容为验收对象；网页接口是否可用须在开发初期实测，不能以模拟数据代替功能验收。

项目暂用工作名“鸿蒙微博客户端”。工作名不表示微博官方产品；正式显示名称和包名在个人安装前确定。

## 2. 首版范围

| 模块 | 用户可完成的事 | 验收条件 |
| --- | --- | --- |
| 登录与退出 | 在微博网页中使用其提供的扫码、手机号验证码或密码方式登录；退出当前账号 | 登录后能读取本人信息和关注列表；退出后受保护内容及写操作要求重新登录；应用不接收密码或验证码 |
| 首页 | 在“关注”和“热门”之间切换，下拉刷新、向下加载更多 | 两类内容来自实时接口；刷新不会混入旧页数据；分页不重复展示同一条微博 |
| 搜索 | 输入关键词搜索微博并进入详情 | 有结果、无结果、请求失败均有不同状态；点击结果能打开对应详情 |
| 微博详情 | 查看作者、正文、时间、图片或视频、互动数及评论 | 长文、转发内容和多图在接口返回时正确呈现；缺失字段不造成崩溃 |
| 评论 | 查看评论、发表评论 | 提交成功后显示服务端返回的评论；失败时保留输入内容并说明原因；未登录不可提交 |
| 点赞 | 点赞及取消点赞 | 以服务端确认结果为准更新状态和数量；失败时保持原状态；重复点击不产生并发请求 |
| 个人主页 | 查看本人及从微博跳转到的用户资料与已发布微博 | 资料与微博列表对应同一用户；分页与空状态可用 |
| 视频 | 在应用内打开和播放信息流中的视频 | 可播放资源能开始播放、暂停和返回；不可播放时明确提示，离开页面后停止播放 |

首版不包含发微博（文字、图片或视频）、转发、关注管理、私信、通知、多账号、离线下载和应用市场上架。微博中的普通网页链接可交由系统浏览器打开。

## 3. 页面与主要流程

1. **启动**：检查本机微博网页会话。未登录仍可进入可访问的热门内容；关注、评论、点赞和“我的”引导登录。
2. **登录**：打开微博自己的登录网页，用户选择网页实际提供的方式。扫码需要另一台已登录微博的设备；页面不提供的方式不自行仿造。登录完成后回到原操作，失败或取消则保持原页面。
3. **浏览**：首页双页签 → 微博详情 → 评论或视频；作者头像和昵称进入个人主页；搜索结果进入同一详情页。
4. **互动**：用户提交评论或点击点赞 → 显示进行中 → 收到微博服务端确认后更新 UI。请求失败允许用户重试；评论请求结果不明时先查询详情，避免重复发送。
5. **退出**：在“我的”中退出，清除本应用的微博会话并返回未登录状态。

## 4. 界面状态与体验

- 每个列表区分初次加载、正常内容、空结果、加载更多、网络失败和登录失效；失败时提供重试入口。
- 图片按需加载，列表滚动位置在详情返回后保留。视频默认不自动播放，使用移动网络时也由用户点击启动。
- 正文保留可读文本、话题和链接的基本呈现；不支持的富文本元素以安全文本显示。
- 支持系统深浅色、文字放大、安全区和基础无障碍标签；避免把页面操作依赖于颜色或手势。
- 评论和点赞等写操作只由用户明确触发；不在后台自动执行。

## 5. 交付与验收

首版完成需同时满足：HarmonyOS 7 手机上可安装和启动；本人账号能完成登录、关注列表读取、评论发布与点赞；热门、搜索、详情、主页、视频均通过真实内容走查；构建与必要测试通过。每项验收记录使用的设备、系统版本、日期及结果，不保存或展示 Cookie、密码和验证码。

若微博网页接口变化、风控或账号权限使某项能力无法完成，界面应显示真实失败状态，并在验收记录中标明“未通过”；不能用模拟数据宣称该项完成。个人使用不代表接口长期稳定。

## 6. 外部依赖

数据接入参考开源项目 [jackwener/weibo-cli](https://github.com/jackwener/weibo-cli) 和 [wedaren/agentic-weibo-cli](https://github.com/wedaren/agentic-weibo-cli)。这些项目使用微博网页接口和网页登录态；本项目须独立验证接口响应及登录流程。微博开放平台的[正式服务说明](https://open.weibo.com/cli/quickstart)涉及开发者认证和服务开通，当前没有对应凭证或权限。
